# 原序
:::tip 提示
这是本书的原序
:::
在开之前，我想跟读者，也就是你，坐下来浅谈几句。

1.

一提起“计算机”，你大概会想到桌上的笔记本电脑，或者口袋里的手机。
它们当然是计算机。但本书要聊的，不止它们。电子表是计算机。它数着晶振的每一次跳动，准时在屏幕上加一秒。
洗衣机是计算机，它读着传感器的信号，决定还要转多久。
智能门锁也是计算机，在验证你的身份时他的CPU 已经计算了上千次
凡是带芯片的、有电路板的、能计算的，不管长得像不像电脑，本书一概管它们叫“计算机”。
书名就叫《计算机》。最朴素，也最宽大。不加修饰，因为这三个字已经够装了。

2.

书分两大部分：软件篇和硬件篇。
从软件开始。原因很诚实：轻。你只需要一台普通电脑，写一行代码，屏幕上立刻跳出结果。这种即时的正反馈，是最好的入门甜点。硬件篇在后面等着，那里比较烧脑。但等烧到那里时，你已经不是新手了。
“软件”也不止写几行代码。我们会碰到框架 、游戏引擎 、操作系统 、数据库 。它们不会一拥而上，而是一个一个来。每章只解决一个小问题，写完就能跑。

3.

有几件事，需要事先告诉你。

第一，这本书是边学边写的。作者不是什么资深专家，而是一个正在学习的人。会的就写，不会的就说“这个我也不太熟，我们一起看看”。这不是谦虚，是这本书本来的设定。

第二，知识会过时。计算机是个跑得飞快的领域。当你读到这些文字的时候，某些工具的版本可能已经迭代，某些“最佳实践”可能换了说法。每个板块的开头都标了撰写日期，那是这些知识的出厂标记。如果发现不对劲，请先看看日期——时效性的锅，不该由当时的你和当时的我来背。

第三，可能有错误。作者的知识有边界。本书追求准确，但不保证无误。如果哪里讲错了，那不是故弄玄虚，是我当时真的那么理解。如果你发现了，请告诉我。这本书是活的，错误会在未来的版本里修正 。

第四，这本书没有“完结”这个概念。它用很长时间来生长。你读到的，只是它生命中的一个切面。有些章节可能还没动笔，有些可能重写了好几遍。这都不是bug，是设定。如果你哪天看到它完结了——那意思恐怕不是写完了。是作者放弃了，或者逝世了。

第五，作者并不擅长写作，所以这本书可能没有其他人写的那么好，请你谅解。

4.

所以，这不是一本传统的教程。它更像一张正在绘制的地图，作者也在边走边画。有些地方画得细，有些地方还空着。但如果你愿意，欢迎你和作者一起，把这张图画下去。

我们开始吧。
